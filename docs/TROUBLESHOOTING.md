# 排错指南

## 面板绘制失败

如果看到“自定义面板绘制失败”：

1. 记录完整错误文本和面板名称。
2. 确认插件是最新版本。
3. 在全局设置中执行“清除缺失面板提示”。
4. 刷新面板库。
5. 如果错误来自第三方插件，先禁用该插件的自定义面板或升级第三方插件。

不要在面板 `draw()` 阶段直接写入 `Scene`、`Object` 或其他 Blender ID 数据块。自定义脚本需要写状态时，应通过运行操作器完成。

## 预设导入卡顿

大型预设可能包含多个工作流、脚本源文件和 AI 说明。

排查顺序：

1. 使用最新 Release。
2. 先点击“载入预设”，不要直接反复点击导入。
3. 只导入一个工作流。
4. 检查脚本库和 `_imported_presets` 是否存在大量重复文件。
5. 重启 Blender 后再试一次。

GoWorkFlow 会按脚本内容计算摘要并复用相同资产，重复导入同一预设不应持续生成同内容文件。

## 全局状态文件损坏

状态文件默认位于 Blender 用户配置目录下的 GoWorkFlow 配置区域，文件名通常为：

```text
go_workflow_global_state.json
go_workflow_global_state.json.bak
```

处理方式：

1. 关闭 Blender。
2. 备份这两个文件。
3. 优先保留 `.bak` 文件。
4. 重新启动 Blender，观察是否能从备份恢复。
5. 不要在 Blender 正在运行时手动编辑状态文件。

## Blender 4.5 兼容问题

Blender 4.5 对部分 RNA/ID 数据块写入时机更敏感。GoWorkFlow 已针对以下路径加入保护：

- 全局状态恢复
- 预设工作流导入
- 失效面板分组和标题绘制
- 异常字符串和超长文本写入

如果仍然崩溃，请提供：

- Blender 精确版本
- GoWorkFlow 版本
- 触发操作的步骤
- `blender.crash.txt` 中的 Python backtrace
- 是否使用了特殊预设或第三方面板插件

## 预设缺少面板

这通常表示目标环境没有安装原预设依赖的第三方插件，或者第三方插件更新后改变了面板 ID。

可以尝试：

- 安装对应第三方插件。
- 刷新面板库。
- 使用“重新查找缺失插件面板”。
- 手动重新选择目标面板。

## 提交 Issue 前

请不要直接上传包含模型、个人路径、完整用户配置或隐私数据的压缩包。先删除：

- `.blend`、`.fbx` 等模型文件
- 用户目录绝对路径
- 与问题无关的脚本资产
- 第三方插件源码

使用仓库的 Bug Report 模板提交最小可复现信息。
